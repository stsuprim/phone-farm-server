# Mac mini steps for the 2026-11-15 update (idle lock, WDA re-sign, profiles, thumbnails)

For Rinor: paste everything below the line into Claude Code on the Mac mini, started inside the project folder
(`phone-farm-server`). It needs you at the Mac for a few clicks (Xcode sign-in, macOS permission prompts, the phones).

---

You are updating the "Phone Farm Server" on this Mac mini. Read `README.md` (sections "API" and "Idle lock, WDA re-sign,
profiles and thumbnails") first. Work step by step, run each check, and stop and tell me when a step needs me (Apple ID
sign-in, a macOS permission prompt, unlocking a phone, "Trust This Computer"). **Never print, log or paste `.env` or the
API token**; use it only inside commands through shell variables, as below. Don't `git push` anything.

Set these once in your shell for the checks (they read `.env` without printing it):

```sh
cd ~/phone-farm-server   # or wherever the project is (the plist's WorkingDirectory)
set -a; . ./.env; set +a
B="http://localhost:${PORT:-8787}"; H="Authorization: Bearer $API_TOKEN"
```

1. **Get the new code.** The auto-updater pulls GitHub main within about a minute. Confirm:
   `git log --oneline -1` mentions idle lock / WDA re-sign, and `ls src/idle.ts src/resign.ts docs/MAC_STEPS_2026-11-15.md`
   lists all three. If not: `curl -s -X POST -H "$H" $B/update/now`, wait 60 s, check again.

2. **Phones: Developer Mode, trust, no passcode.** On each iPhone:
   - Settings > Privacy & Security > Developer Mode = On (it reboots; confirm "Turn On" after the reboot).
   - Plug it in, unlock it, tap **Trust This Computer** and enter the phone passcode. Check: `idevice_id -l` lists every
     UDID and `ideviceinfo -u <UDID> -k DeviceName` prints its name.
   - Settings > General > VPN & Device Management: trust the developer app (the owner's Apple ID) if it's listed.
   - **Passcode off** (Settings > Face ID & Passcode > Turn Passcode Off) on farm phones: the server's wake can only get
     past the lock screen when there's no passcode. With one, `wake` answers `locked: true` and a `warning`.
   - Settings > Display & Brightness > Auto-Lock = Never is fine: the server now locks idle phones itself.

3. **macOS permissions** (System Settings > Privacy & Security). Ask me to click; don't change anything else:
   - **Camera**: `PhoneCap` must be allowed (the H.264 capture of the phone screens is a camera device to macOS). Run
     `native/phonecap/build/PhoneCap.app/Contents/MacOS/phonecap --request-access` once after step 6 if it isn't listed.
   - **Screen Recording** and **Accessibility**: not needed by the server itself. Grant them only to Terminal / the
     `node` binary if macOS shows a prompt for them (e.g. when Xcode or the capture helper asks); tell me which app asked.
   - **Developer Tools**: allow Terminal (Privacy & Security > Developer Tools) so `xcodebuild` runs without prompts.
   - **Keychain**: when `xcodebuild` asks for the login keychain during signing, I click **Always Allow**.

4. **Xcode signing with the owner's free Apple ID.**
   - `xcode-select -p` must point inside `/Applications/Xcode.app`. `xcodebuild -version` works.
   - Xcode > Settings > Accounts: the owner's Apple ID is signed in (I'll type the password; never ask me to paste it to
     you). Select it, note the **Team ID** (Personal Team, 10 characters).
   - Check: `security find-identity -v -p codesigning` lists an "Apple Development" identity.
   - Put the Team ID in `.env` without printing the file:
     `grep -q '^WDA_TEAM_ID=' .env && sed -i '' 's/^WDA_TEAM_ID=.*/WDA_TEAM_ID=<TEAM_ID>/' .env || echo 'WDA_TEAM_ID=<TEAM_ID>' >> .env`
     (`WDA_RESIGN=true` and `WDA_RESIGN_HOUR=3` are the defaults; add them only to change them.)

5. **First WDA build per phone** (the server re-signs every 6 days after this, at 03:00-06:00):
   `scripts/build-wda.sh <TEAM_ID> $(idevice_id -l | tr '\n' ' ')`
   If it fails, read the "First errors" it prints. "No Accounts" / "requires a development team" = step 4; "Developer
   Mode" = step 2; "device is locked" = unlock the phone; a free-account limit ("maximum number of apps") = remove
   old WebDriverAgent copies from the phone or wait 7 days. Then on each phone trust the developer (step 2) if asked.

6. **Rebuild the native helpers and the server.**
   - `npm install && npm run build` (TypeScript to `dist/`, then the phonecap capture helper; it got an encoder
     latency change). Check `cat native/phonecap/build/phonecap.caps` says `lanes` and
     `native/phonecap/build/phonecap.error` doesn't exist (if it does, show me its first error line).
   - HID touch helper (only if a phone runs iOS 27+): it's Python, no build; update it with
     `~/.phonefarm-hid/bin/pip install -U pymobiledevice3`. On iOS 18 phones skip this.
   - `npm test` must end with every suite passing (mock mode, no phones touched).

7. **Reload the launchd service** (the plist is `~/Library/LaunchAgents/com.lotus.phonefarm.plist`):
   `launchctl bootout gui/$(id -u)/com.lotus.phonefarm 2>/dev/null; launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.lotus.phonefarm.plist`
   then `launchctl print gui/$(id -u)/com.lotus.phonefarm | grep -E 'state|pid'` shows it running. Wait 30 s.

8. **Check it works** (show me only the JSON, never the token):
   - Status: `curl -s -H "$H" $B/api/status | python3 -m json.tool | head -60` -> `settings.idleLockMinutes` 10,
     `wda.state` `ok` with `daysLeft` about 7 (or `expired`/`failed` with `lastError`: fix that first), and each
     device with `locked`, `screenOn`, `lastActive`, `stats.video_path` (`h264` expected; `mjpeg` means read `stats.h264_reason`).
   - Settings: `curl -s -H "$H" $B/api/settings` then
     `curl -s -X PUT -H "$H" -H 'content-type: application/json' -d '{"idleLockMinutes":10}' $B/api/settings`.
   - Lock and wake one phone (watch it): 
     `curl -s -X POST -H "$H" $B/api/devices/<UDID>/lock` -> `{"ok":true,"locked":true,"screenOn":false,...}`, the screen
     goes off; `curl -s -X POST -H "$H" $B/api/devices/<UDID>/wake` -> `locked:false`, the phone is past the lock screen.
     A `warning` about a passcode = step 2.
   - Swipe as one command: `curl -s -X POST -H "$H" -H 'content-type: application/json' -d '{"points":[[200,700,0],[200,500,80],[200,250,200]],"duration":250}' $B/api/devices/<UDID>/swipe`
     -> `{"ok":true,"via":...}` and one smooth scroll on the phone.
   - WDA signing: `curl -s -H "$H" $B/api/wda`. To test the re-sign path now (takes a few minutes, the phones' WDA
     restarts): `curl -s -X POST -H "$H" $B/api/wda/resign`, then poll `curl -s -H "$H" $B/api/wda` until `state` is
     `ok` (or `failed`: show me `lastError` and `perDevice`). An Xcode that isn't signed in shows
     `"Xcode is not signed in to the Apple ID ..."`.
   - Idle lock: set `{"idleLockMinutes":1}`, close every viewer, wait ~90 s: the phones lock and `/api/status` shows
     `locked:true`. Open the Phones page in Lotus: the phone wakes by itself. Put it back to 10.
   - Logs: `grep -E '\[idle\]|\[wda-sign\]|\[phonecap' server.log | tail -30`.

9. **Report back**, per phone: iOS version, `wda.state`/`daysLeft`/`lastError`, lock and wake worked (and how long the
   wake took), `stats.video_path`, and any `[wda-sign]` or `[idle]` errors in `server.log`.
